Schedules run an agent prompt later, on a recurrence, in a fresh conversation. Use create_schedule for a new recurring cron schedule: give it a short name, a self-contained prompt that includes every needed detail (conversation history is not copied), and a five-field cron expression with an IANA time zone. Confirm the time zone from the user's request; when none is given, say which one you assumed.

For a one-time run, or to rename, pause, resume, reschedule, or delete a schedule, read the agent_schedule schema with resource_read and include_schema: true, then use resource_mutate. A one-time recurrence is {kind: "once", fireAt} with a canonical UTC timestamp. Before creating, search existing schedules to avoid duplicates. After saving, report the schedule by name and id with its next fire time in the user's time zone. agent_schedule_occurrence records each accepted fire and links to the conversation it started.
